This release is about pixel-exact output. A new **Exact** projection mode
copies the canvas to each display pixel for pixel. Every output can now show
whether its mapping is verified as whole-number. Slices can be stored and
edited in whole pixels, and you can choose how scaled outputs are resampled.
System profiles can also save and activate just the parts you choose.

## New

### Exact projection mode

The mode toggle on the Displays tab now reads **Exact | Simple | Warp**.
Exact puts exactly one canvas pixel on each output pixel, with no scaling,
no correction and no resampling. Use it for LED walls, tiled panels, and
content made at the wall's resolution.

- Exact enforces its rules, each with its own message: output scale 1, no
  warp pins, and a whole-pixel slice inside the canvas exactly the size of
  the output.
- Before switching in, the web UI asks what the switch would do. A layout
  that already fits is kept. One that doesn't is reset to exact defaults
  after you confirm, with the reasons listed. Switching back out changes
  only the mode, so a round trip leaves the layout as it was.
- **Arrange automatically** works in whole pixels in Exact. Overlaps are set
  in pixels, and the canvas is sized to fit the arrangement.
- Controls that would scale the picture are hidden or locked in Exact.
- An appliance that tiles its displays without the canvas slicer is already
  one-to-one, so there Exact is disabled with that reason.

[Projection modes](https://suede.gameshow.pro/projection-modes/) describes
all three modes on one new page.

### A "1:1 verified" chip on every output

Each output in the Displays diagram and the output editor shows a chip when
the daemon confirms its mapping is whole-number: **1:1 verified**,
**2× whole-number verified** (and so on), or **1:1 (tiled)**. The chip comes
from what the renderer actually reports, not from the settings alone. Its
tooltip lists what was checked. When an output is not verified, the output
editor lists the reasons. The chip holds steady while you drag, and changes
only when a new verdict arrives.
[Read more](https://suede.gameshow.pro/configuration/#whole-number-chip).

### Slices in percent or whole pixels

The **Slice from canvas** panel (formerly Shared content selection) edits
each output's slice as X, Y, Width and Height. A **Percent | Pixels** choice
sets how slices are stored:

- **Percent** slices follow the canvas when its resolution changes.
- **Pixels** slices stay where they are.

Exact mode always uses pixels.

Whatever the unit, Suede now always crops whole canvas pixels. Dragging or
nudging an output in the diagram lands on whole pixels too. A slice that
runs past the edge of the canvas is now accepted, reported with its overhang,
and hatched in the diagram.
[Read more](https://suede.gameshow.pro/configuration/#slice-units).

### Resampling filter

A new **Resampling filter** setting in the Frame timing card chooses how
outputs that are not 1:1 are scaled:

- **Bilinear:** the default, and the cheapest.
- **Nearest:** keeps hard pixel edges.
- **Bicubic** and **Lanczos:** sharper when scaling up.
- **EASU:** offered, but samples bilinear for now.

Whatever the filter, an output shown at less than half size is always
averaged automatically, and 1:1 outputs are always copied exactly. A filter change
takes effect live. The timing table has a new Sampling column showing what
each output actually uses.
[Read more](https://suede.gameshow.pro/configuration/#resampling-filter).

### System profiles: choose apps and sections

- **Saving:** a profile can keep only some apps. The Apps checkbox shows
  all, none or a mix, and **Choose apps…** picks them.
- **Activating:** you can apply only some of a profile's sections. Applying
  some of its apps adds or updates just those apps and keeps the rest of
  this system's apps.
- **Device mapping:** each saved display and audio output has a box where
  you type a name or pick a detected device. The boxes are filled in for
  you: exact matches first, then the next unassigned device. Each says
  which it got.

[System profiles](https://suede.gameshow.pro/system-profiles/) is a new
page that walks through all of this.

### Smaller additions

- A **Coordinates** test pattern encodes each pixel's own position in its
  color, so a capture of any output can be checked against the canvas.
- For a straight grid of outputs, the resolution recommendation is now
  exact. Four 1920×1080 outputs on a 3840 px canvas recommend 3840 px and a
  100% rendering scale, where before the recommendation added a 5% margin.
- The docs have a [Screenshots](https://suede.gameshow.pro/screenshots/)
  page of every tab, and a short overview video.

## Fixed

- Rotated and flipped outputs (90°, 180°, 270° and mirrored) now copy pixels
  exactly at 1:1. Before, they were filtered and could soften the picture.

## Before you upgrade

- **Crops are whole pixels.** A layout whose slice edges fell between canvas
  pixels now crops on the nearest whole pixel. The picture on such an output
  can move by up to half a canvas pixel.
- **Rolling back.** Version 0.4.0 and older cannot read a configuration that
  stores slices in pixels or uses Exact mode. Before going back, switch to
  Percent and to Simple or Warp, or keep a copy of the state file from
  before the upgrade.
- **Fine nudge removed.** The 0.1 px Alt+arrow nudge in the Displays diagram
  is gone, since slices now land on whole pixels.
- **API.** Existing requests behave as before. New fields:
  - `projection.mode: "exact"`, `projection.filter` and
    `projection.sliceUnits`;
  - a per-output `mapping` verdict in control status;
  - `GET /api/v1/projection/exact-transition`;
  - app lists for `includes.apps` when saving a profile, and `sections` when
    activating one.
