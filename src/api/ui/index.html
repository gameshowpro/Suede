Edge blending

The overlaps come from the layout above: drag the displays so they overlap exactly as the beams do on the surface — every seam its own amount. Suede renders the app once into that canvas and slices it per projector; with blending on, each seam is faded from both sides so the doubled light adds up to one seamless picture.

These settings are inactive: no displays overlap and no shared canvas is configured. Position displays so they overlap — as the projector beams do on the wall — or calibrate geometry to engage blending.

Overlays two-pixel lineup marks on every output while it is on: orange where this output's own blend starts, blue at the far edge of the overlap. Adjust warp until the two colors line up as white. Never saved — it always comes back off.

Gamma shapes the fall-off — the projectors' transfer curve, usually 2.2. If seams glow on dark scenes (projector black is not zero light), raise the compensation until the rest of the picture matches them.

Frame timing

Off, every display takes each frame together and the next frame waits until all of them have taken it. On, each display takes the newest frame as soon as it is ready — only for displays that cannot be made to share a refresh rate, and the wall stops being in step.

Auto blends on the GPU when the compositor and driver support it, and falls back to the CPU otherwise — the slicer logs which it picked and why. CPU always uses the fallback path. GPU forces the GPU path and refuses to start if it is unavailable, rather than silently running slower.

OutputPresentedDiscardedZero-copyRefreshPhaseLag

Measured by the slicer over each 10 s interval from the compositor's presentation timestamps. Offset is how far apart the displays showed the same frame; a straddle is a frame they showed on different refreshes. A gate hold is a commit the wall delayed past a canvas period waiting for an output to report presenting the previous frame — the others repeated a frame rather than move on without it. Lag is a per-output histogram (zero/one/two/three-or-more) of how many whole refreshes behind the earliest output this one presented — read it against a photograph to tell a presentation-path slip from the display's own processing latency. Healthy: a steady offset of a few milliseconds and no straddles.

Arrange outputs

Enabled outputs are placed left to right, then top to bottom. The daemon does the arithmetic. Both overlaps are honored exactly: the content scale (100% = 1:1 pixel sampling) is the one that fills the canvas on whichever axis binds first, so the canvas may be left partly unused on the other axis — the line below says how much, and which canvas aspect would fill it. Setting the content scale instead derives both overlaps and fills the canvas on both axes.
